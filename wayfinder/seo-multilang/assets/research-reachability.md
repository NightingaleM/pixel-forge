## 2. 文献取证（2025–2026 来源，均附链接）

### 2.1 中国大陆服务器国际链路的已知状况

- **跨境 RTT 基线**：中美西部正常 RTT 150–220ms，美东/欧洲 250–300ms 属正常预期；国际出口晚高峰（20:00–23:00）拥塞时延迟与丢包同步上升。——《跨境网络卡顿排查：用MTR与iperf3三步定位丢包根因》CSDN，2026-09-08，https://blog.csdn.net/weixin_42525637/article/details/164742422
- **国际出口拥堵量级**（营销类文章，数字供参考需打折）：国际出口高峰利用率可超 80%，晚高峰丢包率可达 15–20%。——搜狐，2025-10-23，https://www.sohu.com/a/946815379_121672393 ；同类文章称欧美用户访问中国大陆服务器平均延迟 200–350ms，SSL 握手在高 RTT 链路上多耗 3–4 个 RTT。——搜狐，2025-10-30，https://www.sohu.com/a/949178408_121672393
- **香港中转劣化的实证**（与本次 HK 探测 324–1324ms 互证）：直连香港服务器 TCP 重传率可高达 15%，实测直连平均 78ms+2% 丢包，经深圳节点内网中转后 21ms/0 丢包。——《用阿里云双节点（香港+深圳）搞定MT4/MT5大陆访问难题》CSDN，2026-05-11，https://blog.csdn.net/weixin_42525637/article/details/160974047
- **不稳定性机理**：国际出口带宽有限、BGP 路径不固定（绕行可致延迟翻倍）、晚高峰拥塞、三大运营商互联质量差异。——搜狐，2026-04-08，https://www.sohu.com/a/1006774372_121975103

### 2.2 ICP 备案与海外访问的关系

- 备案拦截针对的是「大陆服务器 + 未备案域名」组合，由云厂商在接入层拦截 80/443，**拦截范围是中国大陆内，海外用户访问不受影响**。——hzjcp，2026-02-18，https://www.hzjcp.com/210101.html ；中华网科技，2026-08-05，https://tech.china.com/articles/20260805/202608051933525.html ；admin5 备案流程综述，2026-09-12，https://www.admin5.com/tags/wangzhanbeianliucheng/
- 推论：本站当前境内外均可正常访问，说明未触发未备案拦截；**备案状态本身不是海外可达性的变量**。反之，若迁出到境外服务器，阿里云会取消接入，备案号可能被注销（见 §4 方案 C/D）。

### 2.3 Cloudflare 免费档与大陆源站/大陆用户

- CF 免费档在中国大陆**无落地节点**；主要用户来自海外、国内访问仅占少数时「免费方案完全够用」；国内访问会被调度到港/东京/新加坡等周边节点，质量取决于 ISP 路由。——《Cloudflare CDN 中国大陆访问加速实战配置指南》hostease，https://cn.hostease.com/blog/cdn/cloudflare-cdn-china-acceleration/
- 大陆方向实测口碑：免费版分配 IP 常绕美西走 163 骨干，大陆首访可近 1 分钟，社区需靠「IP 优选」缓解，CF 在大陆被称「减速器」。——知乎专栏，2026-05-11，https://zhuanlan.zhihu.com/p/2037111784696443004
- **大陆源站回源风险**：免费版 CF 节点常在美西，源站在上海/深圳时回源要跨太平洋往返，晚高峰国际出口拥堵丢包时可致 521/522 超时；源站防火墙还须放行 CF 回源 IP 段。——酷番云，https://www.kufanyun.com/ask/843212.html
- 背景：CF 正规大陆节点（原与百度合作的 China Network）需企业版+ICP 备案，个人站不可达。——网易，2017（历史背景），https://www.163.com/dy/article/CKMHKF9K0511FM70.html

## 3. 结论摘要（事实判断）

1. **能打开**：全球 54 个有效探测点中 53 个 HTTP 200（≈98%），唯一失败是达拉斯单点超时；无 GFW 式阻断迹象，备案状态不影响海外访问。
2. **速度量级（跨境低谷期）**：HTML 首字节全链路 0.3–2.8s——日本 0.38s / 美西 0.9s / 欧洲 0.8–1.4s / 巴西 1.4s / 美东 1.7s / 港新 1.3–2.8s；其中 RTT（东京 55ms、美西 166–199ms、欧洲 188–227ms、美东 478–517ms、巴西 334–349ms）占大头，服务器处理 <10ms。
3. **真实首屏会更差**：410KB 静态资源未开 gzip、无 Cache-Control，高 RTT 跨洋 TCP 下海外首屏估 3–6s 量级（未实测吞吐）；晚高峰（北京 20–23 点）链路劣化时再乘一个系数，文献晚高峰丢包可达 15%+。
4. **SEO/爬虫视角**：Googlebot 从美国抓取，TTFB 1–1.8s、成功率 98% → 可正常抓取索引，但 LCP/Core Web Vitals 的海外真实用户数据会被拖累。
5. **白捡的优化**（与是否上 CDN 正交）：开 gzip/brotli（410KB→~120KB）、加 Cache-Control/immutable、HTTP/2、把权威 DNS 迁到离用户近的服务（当前 hichina 境内权威导致海外 DNS 段 200–1750ms）。

## 4. 是否需要 CDN 前置——三方案事实对比（不决策）

| 方案 | 海外效果 | 大陆用户效果 | 成本/工程量 | 主要风险与注意 |
|---|---|---|---|---|
| A. 维持直连+站点级优化（gzip/缓存头/h2/DNS） | 首字节不变（RTT 决定），首屏 3–6s→1.5–3s | 不变（最优，50–60ms） | 0 元，改 nginx/构建配置 | 晚高峰劣化仍在；无 DDoS 隐藏源站 |
| B. Cloudflare 免费档前置 | 静态 SPA 缓存命中后全球边缘 <100ms 级，收益最大；DNS 迁 CF 顺带消灭慢解析 | **变差**：绕美西 163 骨干，200ms+ 且不稳（文献 §2.3）；需 IP 优选缓解 | 0 元；NS 迁移 + 回源配置 | miss 回源跨太平洋可 521/522；源站须放行 CF IP；免费档无 SLA；「大陆用户体验降级」是明确代价 |
| C. 阿里云 CDN（全球/海外区） | 海外走亚太1（港新 GIA）/北美/欧洲节点，TTFB 降至 <100ms 级；回源仍走公网跨境 | **不受损**：大陆走国内节点（域名需已备案，本站可用） | 月 <10GB 流量约 ¥50–150/年（§2.4） | 回源带宽与命中率决定实际效果；证书/缓存规则配置量；账单随流量增长 |
| D. 迁国际托管（Vercel/CF Pages/港新 ECS） | 最优：海外用户就近 <50ms | 最差：150–300ms+ 不稳；且源站迁出后阿里云取消接入，**备案号可能被注销** | 迁移工程 + 新托管成本 | 与「保留大陆可达性」目标冲突最大 |

补充事实：本次实测的香港路径劣化（324–1324ms）提示——任何「迁香港就算海外+大陆兼顾」的直觉需要实测验证，香港↔大陆跨境互联本身就有拥堵前科（§2.1）。
