# 2D 会员制(水印墙 + 激活码)设计文档

日期:2026-09-25
状态:已确认(水印墙形态、激活码归属、后端边界、收款路线均经用户逐项确认)
范围:仅 2D。3D(App3D / RecordingControls)不做任何收费相关改动。

## 背景与地基事实

2D 的渲染与导出 100% 在浏览器完成(WebGL/Canvas2D,导出走 `canvas.toBlob`),
批量亦是纯前端。因此**任何免费/会员限制本质上都是君子协定**:前端 JS 可读可改,
localStorage 可清。设计目标不是防破解,而是把白嫖的麻烦程度做到超过日卡价格,
同时守住"零边际成本、无服务器渲染"的产品性质。

收款环境:网站与服务器在境内(阿里云),域名 pixelforge.oylz.site,已有 ICP 备案,
国内优先。后端为新项目 micro_server_nest_ai(NestJS,含后台管理系统,由用户自行开发,
本项目只交付需求文档:见 `docs/2026-09-25-backend-license-api.md`)。

## 付费墙矩阵(定稿:「甜头+降级墙」)

| | 免费 | 会员 |
|---|---|---|
| 单图导出 | 每日 5 次无水印;超出后无限次,带角落轻水印 | 无限次,无水印 |
| 批量导出 | 可用,每张全图平铺水印(不消耗亦不享受无水印额度,额度仅作用于单图) | 可用,无水印 |
| 次数计数 | 仅计"无水印额度",localStorage | 无 |
| 后端依赖 | 零 | 零(离线验签) |

**多码策略**:localStorage 单键只存一个码。激活新码时与现存码比较,保留 `exp`
更晚且验签通过者(续费=发新码,无叠加计时)。

心理路径:先尝到无水印导出的甜头 → 第 6 次起降级水印(损失厌恶) →
批量需求撞上平铺水印(刚需付费)。

**设计原则:后端是增强,不是依赖。** 后端未部署/不可用时,前端全部功能照常,
仅丢失"防分享绑定"与"邮箱找回"两项增强(v2 后端能力)。

## 模块设计

新增 `src/lib/license/`,三个互不依赖的单元:

| 单元 | 职责 | 依赖 |
|---|---|---|
| `verify.ts` | 激活码解析 + Ed25519 验签,输出 `{active, tier, expAt}` | @noble/curves |
| `quota.ts` | 当日免费无水印剩余次数(读写 localStorage) | 无 |
| `watermark.ts` | 在导出 canvas / SVG 上合成水印 | 无 |

调用方仅两处:App2D 单图导出、runBatch 批量导出。预览画布与底部栏缩略图永不加水印。

## 激活码

**格式**:`PF1.<base64url(payload)>.<base64url(signature)>`,
payload 为紧凑 JSON `{v:1,tier:"day"|"week"|"month"|"year"|"lifetime",exp:<unix秒>}`。
码长约 90 字符,整段可复制粘贴。lifetime 档位字段预留(为将来买断制),首发 SKU 只发
day/week/month/year。

- **验签**:前端硬编码公钥,用 @noble/curves 的 ed25519(纯 JS,~10KB,规避 WebCrypto
  的 Ed25519 浏览器兼容差异)。验签 <1ms,每次需要时现验,不缓存会员状态。
- **存储**:localStorage 键 `pf.license.code` 存**码原文**(购买凭证,清存储后重输即恢复)。
  过期码保留,面板显示"已过期,续费激活"。
- **错误分类**(激活输入框的三种提示):格式不对 / 验签失败(提示联系卖家) / 已过期。
- **密钥管理**:生产密钥对由用户在后端环境生成(生成命令见后端需求文档),公钥填入
  前端常量 `PUBLIC_KEY`;轮换 = 换公钥 + 前端发版。测试密钥对仅用于开发自测,
  `scripts/genLicense.mjs` 持有测试私钥(可进 git),**生产私钥绝不进 git 与构建产物**。

## 生成归属(定稿:后端生成)

正式发码全部走后端 `POST /api/admin/license/generate`(后台管理系统操作,生成即入库,
形成台账),前端仓库的 `scripts/genLicense.mjs` 仅作开发自测工具(测试密钥对)。
决策依据:私钥单点受控(服务器环境变量)、生成即入库的完整台账、可接 webhook 自动化。

## 水印规格

三要素:`PixelForge · <种子码> · pixelforge.oylz.site`(种子码完整嵌入,
看到图的人可输码复现效果,每张免费导出图都是带转化入口的广告)。

| 形态 | 触发 | 规格(初值,实现时微调) |
|---|---|---|
| 角落轻水印 | 免费用户当日无水印额度用完后的单图导出 | 右下角单行,白色 ~60% 透明 + 轻阴影(浅色图可辨) |
| 平铺水印 | 免费用户的批量导出(每张) | 45° 全图平铺,透明度 ~15%,间距 ≈ 图宽/6,字号 ≈ 图宽/40 |

- **JPG 合成顺序**:渲染 → 黑底合成 → 水印 → toBlob(水印不被黑底覆盖)。
- **SVG 格式**(批量 ASCII):`<defs><pattern>` + 覆盖 `<rect>` 实现平铺。防君子定位,
  能被文本编辑器移除与 PNG 裁角同级,可接受。

## 免费计数

- 键 `pf.freeExports.<yyyy-mm-dd>`(日期编进键名,本地时区自然日,跨日自然重置,无需清理)。
- 只存 localStorage:清存储的损害仅为"多得 5 次无水印",接受,不做服务端配额
  (水印墙的红利:免费侧零后端)。

## UI 与文案

- 底部栏/侧栏新增**会员入口**(内联 SVG 图标,遵守项目 UI 规范):面板显示当前状态
  (免费:今日剩余无水印 N 次;会员:档位+到期日)、激活码输入框、"复制激活码备份"按钮、
  购买链接(v1 指向面包多商品页)。
- **提示时机**(一次性,不反复骚扰):第 6 次单图导出 toast"今日无水印额度已用完,
  本次起带水印";批量面板顶部常驻细横幅"免费版批量导出带水印"。
- 文案走现有 i18next(中英两份)。
- 会员过期:自动降回免费逻辑,面板提示续费,无打断弹窗。

## 后端需求(摘要,全文见独立文档)

**v1(上线必需)**:`POST /api/admin/license/generate`(后台鉴权)+ 表 `license_codes`。
**v2(自动化阶段)**:`POST /api/license/activate`(设备绑定,上限 3 台)、
`POST /api/license/recover`(邮箱找回,依赖 SMTP)+ 表 `license_binding`。
原则:两 v2 接口失败/未部署时前端静默降级纯离线模式,不报错。

## 收款与发卡(三阶段,运营动作非代码)

1. **v1 冷启动**:面包多(个人可开,付款后自动展示文本)上架四档激活码,
   用后端预生成码贴库存;网站购买按钮直链商品页。统计 = 平台销售数据 + 后端生成台账。
2. **v2 自动化闭环**:当面付直连自建售卖(买家站内点购买 → 当面付二维码 →
   支付异步 notify 后端 → 实时生成码 → 页面展示),订单/支付/发码/激活同一数据库,
   发卡平台退出链路。
3. **v3 规模化**:月流水稳定后注册个体工商户 → 官方商户号 → 解除当面付额度限制。
   SKU 价格参考区间:日卡 ¥3~6 / 周卡 ¥9~15 / 月卡 ¥19~30 / 年卡 ¥49~99(用户最终定价)。

## 测试策略

- vitest 单测:验签四例(合法/篡改/过期/格式错)、跨日计数重置、
  水印合成像素级断言(采样角落/平铺区域的 alpha 通道)。
- 集成:走现有 App2D/runBatch 测试体系,覆盖三条 gating 路径
  (免费第 6 次带水印 / 会员全程无水印 / 免费批量平铺)。

## 明确不做

账户体系、服务端渲染/配额、3D 收费、免费侧任何网络依赖、免费批量锁定
(批量始终对免费开放,以水印变现)。

## 决策记录

| 决策 | 理由 |
|---|---|
| 水印墙而非纯次数墙 | 先甜后苦的转化漏斗;免费批量开放让价值可感知,平铺水印是批量用户刚需痛点 |
| 离线验签而非联网验证 | 纯客户端架构下服务端强制是幻觉;离线验签零后端依赖、零延迟、后端故障不影响用户 |
| 后端生成而非本地脚本 | 私钥单点受控、生成即入库台账、可接 webhook 自动化(用户后端有后台管理系统) |
| 账户体系无限期推迟 | 其核心卖点(服务端强制限额)在本架构下不成立;持久性问题由"存码原文+重输恢复+v2 邮箱托底"以 1/10 成本解决 |
| 不做服务端渲染 | 保住零边际成本性质;一旦渲染上服务器,商业模式从"卖许可"劣化为"卖算力" |
