# 三项 2D 特效第一批改造设计

**日期：** 2026-09-10

**范围：** 半色调、光影、点彩的基础修正与内置预设

**状态：** 已确认设计，待实施计划

## 1. 目标

在不改变现有 Style ID、参数结构、参数顺序和种子版本的前提下，让半色调、光影、点彩从用途模糊的实验滤镜变成三个定位清晰、默认可用、可通过预设快速获得结果的创作工具。

第一批只处理以下内容：

1. 修正三套 Shader 的基础视觉问题。
2. 调整三套效果的默认参数和说明文案。
3. 为每套效果增加 4 个只读内置预设。
4. 保持历史种子码、用户配置和现有渲染架构兼容。

第一批不增加复合控件、额外纹理、机器学习模型、分色导出或新的种子协议。

## 2. 产品定位与边界

### 2.1 半色调：分色印刷

半色调用于模拟规则网屏、多色油墨分版与叠印网花，面向海报、Zine、复古包装和印刷错觉。

它与现有“网纹底稿”的边界如下：

| 效果 | 核心结构 | 目标观感 |
|------|----------|----------|
| 半色调 | 单色或多色通道网点叠印 | 彩色印刷、网花和油墨覆盖 |
| 网纹底稿 | Sobel 轮廓线、单层漫画网点、纸张噪声 | 黑白线稿和漫画网纸 |

半色调不得复制网纹底稿的轮廓提取、排线或纸张噪声。第一批的差异化能力来自颜色通道独立网屏。

### 2.2 光影：戏剧光调

光影用于保护原图内容的前提下做高光辉光、暗部塑形和画面方向性明暗调节，面向商品图、缩略图和氛围化照片。

第一批不把它描述为物理重打光。参数“光照方向角度”在文案中改为“氛围光方向”，明确它控制屏幕空间的辅助明暗塑形，而不生成基于深度或表面法线的投影。

### 2.3 点彩：有机色点

点彩用于通过疏密变化、随机位置和不同尺度的彩色点重构图像，面向编辑插画、彩色点描和有机海报纹理。

它与半色调的边界是：半色调强调规则网屏和印刷通道；点彩强调由图像内容控制的非规则点密度。第一批不增加更多几何形状。

## 3. 架构

### 3.1 内置预设数据

为 `StyleDefinition` 增加可选的 `presets` 字段。每个内置预设包含：

- 稳定 ID，用于 React key 和匹配状态。
- i18n 名称 key。
- 数值参数映射 `params`。
- 颜色或文本参数映射 `textParams`。

内置预设随风格定义打包，不进入 `localStorage`。用户预设的 `PresetEntry`、存储 key 和增删逻辑保持不变。

内置预设应用时必须经过与用户预设相同的默认值合并和白名单过滤：

1. 以当前 StyleDefinition 的默认值为底。
2. 只接受当前风格中已注册的 uniform。
3. 数字参数必须是有限数值，并按参数上下限和步长归一。
4. 颜色参数必须通过现有十六进制颜色校验。
5. 预设未指定的字段使用风格默认值。

该逻辑应放在可独立测试的库函数中，UI 不自行拼装参数。

### 3.2 预设交互

参数面板顶部内容顺序为：

1. 种子栏。
2. “快速风格”内置预设区。
3. “保存配置／我的配置”用户预设栏。
4. 参数控件。

内置预设区使用紧凑按钮。当前所有受预设管理的数字和颜色值与某一预设完全一致时，该按钮显示选中状态。用户修改任一相关参数后，匹配自然失效，不额外维护“当前预设”状态。

内置预设不可删除、改名或计入“我的配置”数量。应用内置预设后，用户仍可继续调整并保存为个人配置。

### 3.3 渲染架构

- 半色调和点彩继续使用单 Pass fragment shader。
- 光影继续使用现有三 Pass：水平模糊、垂直模糊、合成。
- `ShaderRenderer` 不增加新的纹理单元、FBO 约定或渲染模式。
- 所有循环次数使用 WebGL 1.0 可编译的常量边界。

## 4. 半色调 Shader 设计

### 4.1 坐标修正

当前实现使用旋转后的 UV 同时计算网格和采样原图，导致图像内容随网屏旋转，并在边角发生 clamp 拉伸。

新实现将坐标分为：

- `sourceUv`：始终等于原始 `vUv`，用于读取当前像素或网点对应的原图颜色。
- `screenPx`：以画布中心为原点旋转后的像素坐标，仅用于计算网格 ID、单元局部坐标和网点形状。

若需要按网点中心取样，则把旋转空间中的网点中心通过逆旋转映射回原图像素坐标，再采样原图。不得直接用旋转后的 UV 采样原图。

### 4.2 网点覆盖

沿用现有 `uCellSize`、`uDotScale` 和 `uShape`。暗部覆盖率更高、亮部覆盖率更低。边缘使用与单元尺度协调的抗锯齿过渡，避免当前过宽的平滑区造成方块发光或凸起感。

### 4.3 三种颜色模式

#### 灰度

- 使用一个网屏。
- `uAngle` 为实际网屏角度。
- 以浅色纸张为底，黑色油墨点覆盖；不再输出白点黑底。

#### 彩色

- 把经 `uHueShift` 调整后的源图转换为 CMY 油墨覆盖量。
- C、M、Y 使用三个固定相对角度；`uAngle` 是共同的基准旋转。
- 每个通道独立计算网点半径并进行减色叠印，形成清晰的彩色网花。
- 第一批不增加 K 通道、通道角度滑杆或套印偏移参数。

#### 双色调

- 使用暖纸色与两种固定油墨颜色。
- 两种油墨使用不同的相对网屏角度。
- 根据图像亮度分配两种油墨覆盖量，而不是先生成渐变颜色再乘以单一遮罩。

### 4.4 默认值与预设

默认模式继续为彩色，但默认形状改为圆形，网格尺寸和点缩放调整到能在内置图片上保留主体细节的中等值。

内置预设：

1. `报纸黑白`：灰度、45°、中细圆点。
2. `彩色印刷`：CMY 分色、中细圆点、低色相偏移。
3. `双色孔版`：双色调、明显但不过度的双网屏。
4. `粗颗粒海报`：较大网格和高覆盖率，强调图形化轮廓。

## 5. 光影 Shader 设计

### 5.1 高亮提取

水平模糊 Pass 在计算亮度后先使用 `uThreshold` 生成软阈值高亮，再进行高斯采样；垂直 Pass 继续模糊已经提取的高亮信息。这样中间调不会普遍进入光晕。

为避免硬边，阈值使用宽度为 0.08 的 smoothstep 过渡。第一批不增加独立 knee 参数。

### 5.2 合成

合成 Pass：

1. 从原图读取颜色。
2. 应用受控对比度，不在中间步骤提前截断色彩。
3. 根据原图亮度而非已模糊亮度完成明暗分区。
4. 用高亮 Pass 结果生成着色辉光。
5. 使用 `uLightDir` 生成温和的屏幕空间方向权重。
6. 应用暗部塑形并在最后统一 clamp。

默认值从当前极端位置调整为温和起点，目标是在 `cake.jpg`、`car.jpg`、`car2.jpg` 上首次选择效果时不出现大片高光剪切或暗部糊死。

### 5.3 文案与预设

效果描述改为“戏剧光调”语义；参数 `uLightDir` 的显示名改为“氛围光方向”。Style ID `lightshadow` 和页面中的风格名称“光影”保持不变。

内置预设：

1. `柔和窗光`：低对比、中等阈值、小到中等白色辉光。
2. `商品光环`：较高阈值、较强但收敛的白色辉光。
3. `低调戏剧`：较深暗部、受控高光、低辉光。
4. `冷色霓虹`：冷色辉光、中等暗部和明显方向权重。

## 6. 点彩 Shader 设计

### 6.1 参数语义

- `uDotSize`：基础单元和笔触尺度；值越大，点越大且画面越概括。
- `uDensity`：点的出现概率倍率，而不再通过 `uDotSize / uDensity` 隐式改变同一网格尺度。
- `uRandomness`：点中心偏离规则位置的程度。
- `uSizeVariation`：每个点半径的随机变化。
- `uDotOpacity`：点与固定浅色画布的混合强度。
- `uShape`：保留现有圆／方／三角兼容，但预设以圆形为主，不新增形状。

### 6.2 内容驱动密度

每个候选单元计算稳定 hash，并根据原图内容决定是否放置点：

- 亮度越低，基础放置概率越高。
- 高饱和颜色获得最低保护权重，避免明亮黄色、青色等区域完全消失。
- `uDensity` 对最终概率进行缩放和钳制。

该关系必须保证调整密度时，主要变化是点的数量和留白，而不是同时改变点的视觉尺寸。

### 6.3 减弱网格感

fragment shader 在当前单元及周围 3×3 邻域中查找候选点，使用各单元的稳定随机中心绘制覆盖当前像素的点。邻域循环使用 WebGL 1.0 可编译的常量边界。

随机位置不得随帧变化，避免预览闪烁。第一批没有新的 seed uniform，因此相同图片和参数得到稳定结果。

### 6.4 默认值与预设

默认值应在三张内置图上同时表现出可辨认主体、有明显留白、无整齐珠子墙。

内置预设：

1. `细密色点`：小点、高密度、低到中随机度。
2. `修拉色彩`：中等点、中等密度和大小变化。
3. `松散笔触`：较大点、较低密度、高随机度。
4. `彩纸屑`：高大小变化、较高不透明度，并可使用现有非圆形形状形成图形化效果。

## 7. 兼容性

### 7.1 种子码

第一批不得改变三种效果的以下内容：

- 参数数量。
- 参数顺序。
- 参数类型。
- 数值参数的 min、max、step。
- Style ID 和样式注册顺序。
- `SEED_VERSION`。

因此历史种子仍按相同的混合进制结构解码。改变默认值只影响没有显式参数的首次加载，不改变种子中已经编码的数值。

新增内置预设元数据不参与种子编码。

### 7.2 用户预设

`pixel-forge.presets.v1` 格式保持不变。历史用户预设应用后保留其显式数值；新增内置预设不写入或迁移该存储。

### 7.3 导出与随机

PNG、JPG、SVG 导出流程保持不变。现有随机按钮仍依据 StyleDefinition 参数范围随机化；内置预设不改变随机算法。

## 8. 错误处理

- 内置预设包含未知 uniform 时忽略该字段。
- 数字值为 NaN、Infinity 或越界时，使用现有参数归一规则或回退默认值。
- 非法颜色回退对应参数默认颜色。
- 风格没有内置预设时不渲染“快速风格”区域。
- Shader 编译或 WebGL 初始化继续使用现有错误路径；第一批不增加静默降级实现。

## 9. 测试策略

### 9.1 自动化测试

采用测试先行：

1. 内置预设定义只能引用当前风格已注册的 uniform。
2. 内置预设应用后补齐未指定默认值、过滤未知字段、归一数字并校验颜色。
3. 预设匹配函数在完全匹配时返回对应 ID，任一字段改变后不匹配。
4. 三种效果各有 4 个内置预设且中英文 key 存在。
5. 历史代表性种子在改造后解码为相同参数。
6. 各效果默认值编码、全 min、全 max 往返继续通过，既有码长约束不因预设元数据变化。
7. 用户预设存储、应用和删除回归测试继续通过。

### 9.2 构建验证

运行：

- 完整 Vitest 测试。
- ESLint。
- TypeScript 与 Vite 生产构建。

### 9.3 真实 WebGL 验收

在 Chromium WebGL 环境中，以三张内置图片逐项检查三种效果和全部 12 个内置预设：

- 半色调旋转不改变图像内容方向，四角无拉伸；彩色模式可见多通道网花；灰度和双色模式使用浅色纸张底。
- 光影默认值和四个预设无大面积意外过曝、暗部糊死；只有阈值以上区域产生明显辉光。
- 点彩可见内容驱动的疏密关系；提高密度主要增加点数，改变点大小主要改变笔触尺度；无随帧闪烁。
- 对比模式、重置、随机、保存个人配置、应用种子和三种导出继续工作。
- 使用接近 2K 的内置或本地测试图连续拖动主要滑杆，交互保持可接受的实时响应。

保存三种效果默认状态以及每个预设的代表性验收截图或联系表，供人工比较；截图文件放在已忽略的 `artifacts` 目录，不作为运行时依赖或提交内容。

## 10. 后续批次

以下明确不属于第一批：

- 半色调的 K 通道、通道角度编辑、套印偏移、纸张纹理和分色导出。
- 光影的画布拖拽光源、点光／聚光形状、衰减控件、深度或主体分割。
- 点彩的蓝噪声纹理、可调随机种子、Voronoi 迭代、边缘流向笔触和可编辑色板。
- 新的二维点控件、多颜色调色板控件和新版种子协议。

完成第一批视觉验收后，再根据效果辨识度和性能数据决定第二批优先级。
