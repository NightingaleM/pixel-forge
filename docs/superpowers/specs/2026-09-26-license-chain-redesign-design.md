# 兑换码链式语义重设计(身份码/补充包/次数)设计文档

日期:2026-09-26
状态:**待确认**(本文档取代 2026-09-25 spec 的"多码策略"节与后端文档第 3 节 redeem 契约;系统未上线,无历史码与用户兼容包袱,旧格式直接不认)
范围:仅兑换层语义、凭证格式、设备策略。水印墙形态、免费计数、收款三阶段、`generate` 接口均不动。

## 背景与动机

现行方案(2026-09-25)三个反直觉语义,经用户逐场景推演确认不可接受:

1. **多码取最晚到期,时长不叠加**——行业时长码主流是叠加(PS Plus/任天堂会员/国内卡密充值),囤码续费是发卡场景常态;
2. **会员期内兑短码 = 后端消费、前端丢弃**,零收益且无提示;
3. **已兑换码是不记名凭证**,复制到任何设备无限用,兑换层的 3 台限制形同虚设。

行业调研结论:无账户方案的强限制形态是**卡密即身份**(国内网络验证系统标准形态),其代价是使用期依赖服务端存活。本设计取两者之长:

> **码即身份(链式记账)+ 兑换依赖后端 + 使用不依赖(离线验签)。**

## 核心概念

| 概念 | 定义 |
|---|---|
| 未兑换码 | 不变:`{v:1,tier,iat}`,generate 产出,永不过期,囤库存零损耗 |
| **身份码** | 第一个被无会员设备激活的未兑换码,成为**链**的根,服务端记账键 |
| **补充包** | 在续费入口被消耗的未兑换码:链 `exp += 时长`,本身即刻死亡,任何地方不可再用 |
| 链 | 服务端记账单位,键=身份码 code_hash。记录:exp、剩余次数、已绑定 deviceId 列表 |
| **隐藏凭证**(原"已兑换码"v2) | 激活/续费/刷新时后端签发的本地凭证 `{v:2,cid,exp,did}`,前端自动存自动验,**用户全程不可见、无需备份** |

用户心智模型:**手里自始至终只有买到的兑换码原文**。激活用码、续费用码、换设备重输码;凭证是实现细节。

## 架构原则

- **不变**:兑换依赖后端,使用不依赖——激活/续费/刷新需联网,此后离线验签,后端故障不影响在期会员。
- **变化**:
  - 兑换层从"一码一兑、max-exp 覆盖"改为"身份链 + 补充包续期 + 次数预算";
  - 凭证格式升级并**内嵌 deviceId**,使设备限制从软变真;
  - "已兑换码离线直达""复制激活码备份""客服手工签发兼容路径"全部退役(凭证设备绑定后失去意义)。

## 码格式

外层不变:`PF1.<base64url(payload)>.<base64url(signature)>`,Ed25519,紧凑 JSON 键序固定。

| 类型 | payload | 说明 |
|---|---|---|
| 未兑换码 | `{v:1,tier,iat}` | 不变 |
| 隐藏凭证 | `{v:2,cid,exp,did}` | `cid`=身份码 code_hash 前 16 hex(链标识);`exp`=链当前到期(unix 秒,lifetime 固定 2100-01-01);`did`=本凭证绑定的 deviceId |

- 凭证不再含 `tier`:链上时长混合来源,档位语义死亡,UI 只展示到期日。
- 凭证不落库:后端按 `{cid,exp,did}` 确定性重签,幂等天然成立。
- 前端验签时校验**本地 deviceId == did**,不匹配判非会员——凭证复制到未绑定设备自动失效,是"次数真限制"的实现基础。

## 计数规则(设备次数)

- 初始 **5**(含首台激活设备;后端常量可调)。
- 每绑定一个**新** deviceId:−1;已绑定 deviceId 再次激活/续费/刷新:0。
- 每个补充包成功消耗:**+1**(无上限;每次 +1 伴随一次购买,天然封顶)。
- 清 localStorage / 换浏览器 / 重装系统 = 新 deviceId = 新设备,照常扣次。
- 次数是链属性,随链存续;**链过期后剩余次数作废**(过期后再买码 = 全新身份链)。
- +1 的自愈价值:次数被烧尽(码泄露或换机频繁)后,购买任意补充包即恢复 1 次,无客服依赖——替代被砍掉的"次数重置工具",且使恶意烧次数无利可图。

## 全场景判定表(终版)

| # | 设备本地状态 | 入口/输入 | 服务端判定 | 结果 | 次数 |
|---|---|---|---|---|---|
| 1 | 无在期凭证 | 激活入口 × 未使用码 | 新链 | 激活,签发嵌本机 did 的凭证 | 新绑 −1 |
| 2 | 无在期凭证 | 激活入口 × 身份码 A,余次>0 | deviceId 已绑? | 已绑:幂等刷新凭证(0 次);未绑:绑定+签发 | 已绑 0 / 新绑 −1 |
| 3 | 无在期凭证 | 激活入口 × 身份码 A,余次=0 | — | 拒绝:**"该兑换码无法再次激活"**(不提 +1——本设备无自救通道) | 0 |
| 4 | 无在期凭证 | 激活入口 × 已消耗补充包 | — | 拒绝:"该码已被使用" | 不扣 |
| 5 | 会员态 | 激活入口 × 任何码 | — | 引导:"已是会员,延长请用续费入口"。**不再自动转补充包** | 不扣 |
| 6 | 会员态 | 续费入口 × 未使用码 B | 链在期 | **B 消耗为补充包**,链 exp += B 时长,返回新凭证 | **+1** |
| 7 | 会员态 | 续费入口 × 他链身份码 | 双身份 | 拒绝:"该码是其他会员的身份码" | 不扣 |
| 8 | 会员态 | 续费入口 × 重输本链身份码 | 同链 | 幂等,刷新凭证 | 0 |
| 9 | 会员态 | 面板"刷新"链接(免输码,自动携凭证) | 凭证合法 | 刷新凭证到链当前 exp(多设备续费后旧设备同步用) | 0 |
| 10 | 任意 | 凭证被复制到未绑定设备 | 前端本地 | did 校验失败 → 判非会员,只能走激活入口重输身份码 | — |

补充语义:续费延长的是链 `exp`(未到期才可续——场景 6 前提"会员态"即此意);链过期后凭证自然失效,回到场景 1。

## 交互设计

- **双入口按状态切换**(取代单输入框位置语义):
  - 非会员:面板只有**激活**入口;
  - 会员:激活入口收起,显示**续费**入口 + 到期日 + 剩余次数 + "刷新"链接。
  - 意图显式化,根除"会员误把新码当激活码输、意外吃进自己链"。
- 续费入口以弹窗形态做在会员面板内(不做独立页面)。
- **"复制激活码备份"按钮删除**,替换为激活成功提示:"请截图保存你的兑换码,换设备需重新输入它"。

## API 契约改造(后端文档第 3 节重写)

### POST /api/license/redeem(公开,核心)

- body:`{ code: string, deviceId: string(1..128), credential?: string }`
  - `credential` = 本地隐藏凭证原文(会员态自动携带;服务端验签 + cid/did 与 deviceId 一致)。
- 行为:
  1. `code` 验签为未兑换码格式,按 code_hash 查库:
     - **status=unused 且无 credential(场景 1)**:建链(status→identity,exp=now+时长),绑定 deviceId(次数不足 → 409),签发凭证;
     - **status=identity(场景 2/3)**:deviceId 已绑 → 幂等重签(0 次);未绑且余次>0 → 绑定 −1 重签;余次=0 → `409 device_exhausted`;
     - **status=identity/supplement 已消耗且带 credential、cid 匹配(场景 6/7/8)**:code 为 unused → 消耗为补充包(status→supplement,回填 chain_hash),链 exp += 时长,次数 +1,重签;code 为他链身份码 → `409 identity_conflict`;同链重输 → 幂等重签;
     - **status=supplement 已消耗、其余情况(场景 4)**:`400 invalid_code`(前端映射"该码已被使用");
  2. 并发续费对链行加锁(事务/行锁),防止同时贴码丢时长;
  3. email 非空 upsert(recover v2 预留,行为不变)。
- 返回:`200 { code: <新凭证>, expAt, count }`(前端仍本地验签返回码,不信响应体)。
- 错误:`400 invalid_code` / `409 device_exhausted` / `409 identity_conflict` / `429`(IP 10 次/分钟)。

### POST /api/license/refresh(公开,新增,场景 9)

- body:`{ credential: string, deviceId: string }` → 验签+did 匹配 → 重签到链当前 exp。
- 返回同 redeem;链过期 → `410 expired`。限流同上。

## 表结构改造(license_codes)

| 列 | 变更 |
|---|---|
| status | `unused` / `identity` / `supplement`(原 `issued`/`redeemed` 废弃) |
| exp_at | 移至链(即 identity 行):链当前到期,补充包行 NULL |
| **count** | 新增(identity 行):剩余可绑定设备数,初始 5 |
| **device_ids** | 新增(identity 行,json string[]):已绑定 deviceId 台账 |
| **chain_hash** | 新增(supplement 行):指向身份码 code_hash |

`license_binding` 邮箱表保留不动(recover v2)。`redeemed_code`/`redeemed_exp_at` 列删除(凭证不落库,确定性重签)。

## 文案清单(售卖端 + 使用端双提醒,不做拦截弹窗)

**售卖端(商品页/发卡说明)**:
- 首次购买:输入码即激活会员;**请务必保存此码**——它是你的身份码,换设备需重新输入;
- 会员期内再购:新码请在网站"续费"入口使用,时长累加到现有会员;
- 一个身份码最多 5 台设备,每次续费 +1 台;会员到期后新码将开新会员(不叠加旧码)。

**使用端**:
- 激活成功:"激活成功,会员至 X。请截图保存你的兑换码,换设备需重新输入它";
- 续费成功:"已延长至 X,可绑定设备数 +1";
- 次数用尽:"该兑换码无法再次激活";
- 会员过期:"已过期,重新激活请输入新兑换码"。

## 已知不设防(诚实边界,与现架构同级)

1. **身份码原文 = 链钥匙**:泄露即白嫖 + 可恶意烧次数;自救 = 买补充包 +1。码即账号的固有代价,文案强调自保管。
2. **localStorage 整体克隆**(凭证+deviceId 一起拷)绕过设备绑定;防君子不防克隆,无账户无心跳体系的物理上限。
3. **时钟回拨**可延长本地凭证判定(离线验签固有)。
4. 前端可改、存储可清的君子协定不变(水印墙设计前提)。

## 明确不做(本版)

次数重置工具、扣减时长工具(退款)、拦截确认弹窗(文案提醒足够)、身份链合并(分叉永久,客服人工处理)、心跳/同时在线验证、`recover` 邮箱找回(维持 v2 规划不变)、3D 任何改动。

## 决策记录

| 决策 | 理由 |
|---|---|
| 链式记账(身份码+补充包)替代一码一兑 | 修复三反直觉:时长累加(问 2/3)、重复用码幂等或明确拒绝(问 1)、烧短码问题根除 |
| 码即身份而非账号 | 无账户体系约束下唯一能实现强设备限制的形态(行业方案 2);UX 上用户只持有原始码 |
| 凭证内嵌 deviceId | 离线使用与真设备限制不可兼得的矛盾,唯一解;复制凭证自动失效,次数从软限制变真限制 |
| 续费 +1 次 | 多端付费用户不被 5 台卡死;次数烧尽的付费自救通道(替代重置工具);使烧次数攻击无利可图 |
| 激活/续费双入口 | 意图显式化,根除误消耗;文案提醒无法拦截手滑 |
| 次数用尽文案不提"+1" | 本设备无自救通道(续费须发生在已绑定设备),提示无效即欺客 |
| 不做次数重置 | 码自保管原则;+1 机制已提供付费自助恢复 |
| 凭证不落库、确定性重签 | 幂等天然成立;多设备各自凭证互不干扰;省一列状态同步 |
